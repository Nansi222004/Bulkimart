# Checkout payment cancellation

Closing Razorpay with “Yes, Exit” calls the authenticated customer endpoint `POST /api/orders/:id/abandon-payment`. It cancels every still-unpaid fulfilment order covered by that payment and restores the cart, reserved physical inventory, coupon redemption and reserved Coins in one MongoDB transaction. Digital items return to the cart without adding physical stock. Concurrent basket additions are merged; repeated dismissal requests do not restore quantities twice. Cancelled order/payment records and gateway attempts remain available for audit.

Checkout clears its saved recovery reference only after cancellation is confirmed, reloads the basket, and shows a cancellation message. It does not show order success or tracking for an unverified payment. If the cancellation request cannot be confirmed, recovery stays available and another checkout is blocked. If settlement wins the race, the backend reports the verified paid status and the paid confirmation remains valid. COD and wallet confirmation behavior is unchanged.

Cancellation fences new gateway attempts. A later verified Razorpay capture for an abandoned checkout is recorded as a refund obligation through the existing refund recovery system; it never revives fulfilment or spends released Coins. This endpoint does not issue a provider refund itself. Customer order-created notifications are sent after payment verification, rather than when an online order is initially saved. The tracking page no longer embeds the pending-payment box; uncertain payments remain recoverable from Checkout.

Verification uses disposable MongoDB replica-set records and controlled frontend/provider fixtures, without production database changes or real payments. Relevant commands: backend `npm run test:payment-notifications`, `npm run test:financial-workflow`; frontend `npm run test:payment-overlays`, `npm run test:checkout`, and `node --test verification/coupon-automation-ui.test.mjs`.
