# Bulkimart Seller — Technical Memory

Short, current facts for future sessions. No secrets, tokens or passwords.

1. **Purpose:** native Android app for approved Bulkimart sellers. Converts the web Seller Panel (`/seller`).
2. **Role and permissions:** seller session = JWT with role claim `seller` (`verifySellerOTP`). The server enforces `protect` → `requireSellerSession` → `requireApprovedSeller`. The panel opens only when `Seller.status === 'approved'`.
3. **Web sources:** `frontend/src/modules/Seller/**` (`routes/index.jsx` gate, `context/SellerContext.jsx` API calls, `components/*Tab.jsx`), `frontend/src/components/{advertising,gst,finance,services}`.
4. **Backend sources:** `backend/routes/seller.routes.js`, `auth.routes.js`, `product.routes.js`, `advertising.routes.js`, `notification.routes.js`, `ticket.routes.js`; `controllers/seller.controller.js`, `auth.controller.js`.
5. **API:** `https://api.bulkimart.in` (`src/config/env.js`). Envelope `{success,data,message,meta}`; errors `{success:false,message,meta.code}`. `/api/sellers/me` and `/dashboard` use bare keys.
6. **React Native:** 0.88.1, React 19.3.0, CLI 20.2.0 (same versions as `mobile-user`). Not installed yet.
7. **Node:** ≥ 20 (machine had 24.19.0; that machine is not trusted).
8. **Libraries:** react-navigation 7 (native-stack, bottom-tabs), axios (HTTP), react-native-keychain (token), async-storage (payout idempotency keys, push flags, device id), netinfo (offline banner), react-native-svg (sales chart), react-native-get-random-values + uuid (Idempotency-Key, deviceId), react-native-image-picker (Stage 2: photos), @react-native-documents/picker (Stage 3: KYC/ticket files), @react-native-firebase/app + messaging (Stage 3: FCM).
9. **Folders:** `src/{config,theme,services,context,navigation,hooks,components,utils,screens/{auth,dashboard,orders,finance,notifications,profile,products,inventory,invoices,reports}}`.
10. **Navigation:** `RootNavigator` picks a stack from `AuthContext.gate` (loading/verifyError → Splash, signedOut → Login, noSeller, onboarding → `OnboardingScreen`, status, approved). Approved = `PushManager` + stack { Tabs (Dashboard, Orders, Products, Earnings, More), OrderDetail, Fulfillment, TrackOrders, Invoices, InvoiceDetail, ProductDetail, ProductForm, Stock, SalesReport, PickupSync, PayoutRequest, PayoutHistory, TaxStatement, Notifications, Profile, EditProfile, Returns, ReturnDetail, Support, CreateTicket, TicketDetail, BusinessSettings, KycDetails }. `navigationRef` (App.js) lets push taps navigate. `screens/auth/OnboardingRequiredScreen.js` is no longer routed (superseded by native onboarding).
11. **Auth:** phone OTP (`/api/auth/seller/send-otp`, `verify-otp`, `{phone,intent,otp}`) → token in Keychain service `com.Bulkimart.seller.session` → `/api/auth/me` + `/api/sellers/me` gate. No refresh token (30-day JWT). Any 401 from the current token → `endSession()`.
12. **API client:** `src/services/apiClient.js`: one axios instance, in-memory token, `ApiError{status,code,message,body}`, 401 handler, 15 s timeout, no automatic retries of writes.
13. **Finance dependencies:** amounts only from `/sellers/finances/{summary,ledger,tax-statement}`, `/orders/:id/financial-breakdown` (paise), `/dashboard`. `utils/financeRead.js` = exact port of the web validators. Payout POST uses `Idempotency-Key` stored per (seller, amount) until confirmed.
14. **Native features used:** Keychain, NetInfo, ToastAndroid, Linking (https tracking/label links, tel:), camera + system photo picker (runtime CAMERA permission on tap), system back via native-stack. Document picker, FCM and downloads are not implemented yet.
15. **Build:** see README. The `android/` folder is generated from the CLI template on a trusted machine. Package `com.Bulkimart.seller`. Stage 2 adds the CAMERA permission and an IMAGE_CAPTURE `<queries>` entry.
16. **Known limitations:** onboarding/KYC, returns, advertising, support and push are web-only. Products: physical retail only (no e-books, Wholesale or bulk upload); saved variants can't be removed in-app; stock adjust hits the first variant (backend rule). Low stock = below 20 (`LOW_STOCK_THRESHOLD`, backend) vs ≤10 in the web Stock tab. Quick Commerce Shiprocket needs the Razorpay fee (web only). Invoices: view only (no backend PDF, no list endpoint). Sales report: server figures only, 30-day series.
16b. **Stage 3:** Onboarding chain start → step1 → step2 → step3 → step4 → submit; completed steps are not re-sent (step4 appends documents). Returns: decision/pickup panels shown by status like the web, and the server enforces them; no exchanges or seller OTP in the backend. Tickets: ≤5 attachments, RESOLVED → reopen, CLOSED → read-only. Push: `platform:'android'` is stored as an app token scoped to the seller role; sign-out deletes the device token; `notificationTarget()` maps route/metadata to screens. Settings: channels, Wholesale request, shop same-day, logo/banner. Bank/KYC are read-only (no safe update API).
16a. **Product upload contract:** multipart `images` (≤5, JPG/PNG/WEBP, ≤5 MB). On edit, any attached image replaces the whole set. Variants are a JSON string. `gstPriceType` is always `inclusive`. `sameDay` is sent on every Shop All edit.
16c. **Stage 4 audit (static):** 102 files; 61 API calls = 53 MATCH / 8 UNKNOWN / 0 MISMATCH (`docs/STAGE_4_INTEGRATION_AUDIT.md`). Rules now enforced: money helpers show '—' for missing values (`kpiMoney`, `orderMoney`, `countText`), never ₹0; PAN, account and UPI masked; KYC images never opened in-app. Backend risks R1–R7 in `docs/BACKEND_CRITICAL_RISKS.md`; build steps in `docs/ANDROID_BUILD_READINESS.md`. Before testing, point `src/config/env.js` at staging.
16d. **Stage 5 (spec only):** backend remediation plan in `docs/STAGE_5_BACKEND_SECURITY_PLAN.md`, API contracts in `docs/BACKEND_API_CHANGES_REQUIRED.md`, tests in `docs/SECURITY_TEST_CASES.md`.
